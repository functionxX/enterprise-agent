# 采购知识库说明

本目录是 RAG 知识库的文档源。启动后通过 **POST /api/v1/documents/upload** 上传索引，
或直接执行 `python -m app.database.seed` 之外使用评估脚本前先上传。

| 文档 | 覆盖内容 | Agent 会在什么场景检索它 |
|------|---------|------------------------|
| `supplier_policy.txt` | 供应商准入条件、年度评估标准（4 分制分级）、风险分级管理、退出机制 | "XX 供应商风险等级怎么判定"、"评估不达标怎么办" |
| `procurement_rules.txt` | 采购八环节流程、审批权限（50万/200万阈值）、合规要求、发票付款管理 | "这笔订单谁审批"、"单一来源采购合规吗" |
| `quality_standard.txt` | 交付率/合格率指标（95%/98%）、交付异常处理、环保合规、验收流程 | "交付率骤降怎么处理"、"环保材料占比要求" |

## 知识库与种子数据、评估集的联动（重要）

知识库文档中写的**标准阈值**（交付率 95%、合格率 98%、风险分级、审批金额）与
`evaluation/ground_truth.json` 的标注用例一一对应；`database/seed.py` 埋的异常
（恒达精密制造交付率骤降 + 发票逾期、华芯半导体高风险 + 订单激增）正是为了让
Agent 能把"查到的数据"与"知识库标准"对照后发现问题。

> 面试演示话术：知识库不是随便找的几篇文档——文档里的每条标准都被评估集
> 反向测试过：Agent 是否能在数据与标准之间建立关联，而不是只做关键词问答。
